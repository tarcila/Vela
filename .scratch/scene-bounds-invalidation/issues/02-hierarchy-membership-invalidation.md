# 02: Automatic hierarchy membership invalidation

**What to build:** Every supported public insertion, erase, clear, Layer removal and slot-reuse operation makes old Scene observations stale automatically, while failed/no-op operations and existing notification behavior keep their semantics.

**Blocked by:** 01
**Status:** resolved
**Milestone:** 1
**Specification:** [Automatic Scene-Bounds Invalidation and Lifetime-Safe Ownership](../spec.md), Implementation Decisions 1–6 and 8–11; Testing Decisions 1–9.

## Current behavior

Public empty-node helpers and direct hierarchy membership operations can bypass explicit Scene notifications. Transform/object helpers normally signal, Layer clear has an existing signal, and other direct destructive operations do not. Explicit-index insertion can create nonmember gap slots, fail on occupied/invalid slots, or reuse an erased slot. Layer handles can survive removal from a Scene. Forest is also used by non-scene Data Trees.

Read completed01 before starting. It supplies the scene-local, lifetime-safe owner/attachment foundation, coherent public revisions, payload invalidation and compatibility controls. This ticket adds actual membership behavior to that foundation, rather than creating an independent counter or changing the ownership contract.

## Desired behavior and acceptance criteria

- [x] Real Scene public empty/transform/transform-array/object/new-object insertion helpers and all supported overloads automatically invalidate both revisions on successful membership changes. Direct Forest and ForestNode first/last and chosen-slot insertion have the same validity guarantee without an explicit manual signal.
- [x] Successful chosen-slot insertion at the next or a higher index and ordinary/chosen-slot reuse have fresh membership/node lifetime. Gap slots remain nonmembers. Occupied/invalid-slot failures and rejected helper lookup add no membership or automatic validity change. Preserve supported ordering, explicit-index semantics and root construction safety.
- [x] Leaf/nonleaf and direct erase, erase-self, subtree clear, whole-Forest/Layer clear, Scene node removal and Layer removal automatically invalidate actual membership changes. Preserve root restrictions, surviving root semantics and established no-op behavior. Removed/reused slots cannot revive old observations. A retained removed Layer is not implicitly re-registered.
- [x] Both getter orders fold changes coherently; repeated reads without edits remain stable, change-away/change-back without intermediate reads stays invalidated, and independent Scenes remain independent. Reuse01's fixed lifetime-qualified bookkeeping and O(1) observation/comparison. Mutation work may scale with the actual subtree operation; that does not permit an additional query-time fingerprint or Scene walk.
- [x] Preserve01's ownership guarantees through insertion temporaries, failed insertions, gap slots, root storage, reserve/append relocation, destruction/clear, retained Layer removal and eventual Scene teardown. Preserve live-owner object counts, destination attachment, precise local histories and surviving lifetime/topology identities. Constructors/destructors are not blind notification points and expiry cannot revive an owner.
- [x] Preserve exact existing Scene-helper, Layer-clear and Scene-removal callback delivery, including existing explicit signals for otherwise empty operations. Raw/direct hierarchy edits add no coarse render/UI callbacks. Mixed helper/direct/destructive batches preserve structural notification batching and update work-coalescing semantics. Keep normal explicit-signal invalidation independently effective.
- [x] Any generic Forest mutation/binding seam is minimal, optional/default-neutral and independent of Scene. Existing generic Forest and Data Tree storage, root behavior, addressing, Observer and serialization contracts remain unchanged without opting into scene tracking. No global container migration or layer-by-layer architecture task is introduced.
- [x] TDD through actual public APIs covers every operation family above with independently expected membership and identities: all helper/direct insertion forms, leaf/nonleaf/root/empty destruction, occupied/invalid failure, gaps, reuse/change-back, Layer removal while retained, both getter orders, stable reads, independent Scenes and explicit controls. Assert exact object counts, callbacks/batching and history/lifetime invariants. Tests fail for a signal-only implementation and for treating allocation/gaps as membership.
- [x] Keep01's payload/owner-destruction/assignment/relocation tests passing together with membership tests. Reuse existing enabled build/install before new public cases, existing integration/broad-editing regressions and applicable full CTest. Run available sanitizers or Valgrind over failure/gap/reuse/destruction/retained-owner/relocation cases, record actual commands and positive counts, and pass formatting/independent correctness review. Baseline tests alone are not membership qualification.

## Out of scope
