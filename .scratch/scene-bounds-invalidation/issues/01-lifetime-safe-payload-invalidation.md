# 01: Lifetime-safe payload invalidation

**What to build:** Public edits to attached LayerNodeData invalidate the owning Scene's observations automatically, with safe ownership when a Scene or Layer dies and no change to existing rendering notifications or precise histories.

**Blocked by:** 05
**Status:** resolved
**Milestone:** 1
**Specification:** [Automatic Scene-Bounds Invalidation and Lifetime-Safe Ownership](../spec.md), Implementation Decisions 1–11 and Testing Decisions 1–9.

## Current behavior

SceneIdentity normally advances SceneRevision and InspectionRevision from explicit UpdateDelegate notifications. Public local/ancestor transform and enablement edits can change precise local history without invalidating those whole-Scene observations; instance-parameter mutations also lack automatic dependency tracking. LayerNodeData holds a raw Layer association, and Layer holds a raw Scene association. Retained shared Layers and detached object-containing payloads can survive their original owners. Copy/assignment, genuine move-out and storage relocation require different attachment and lifetime semantics.

The spec records the user-approved contract. Historical camera/capture authorization 29 and execution record 42 describe the findings, not completed source work. The earlier ownership/invalidation attempts stopped before implementation. Existing encoder work is separate and must not be reopened.

## Desired behavior and acceptance criteria

- [x] With real Scenes and public APIs, attached local/ancestor transform matrix/SRT/exact-state/default restoration, enablement/ancestor enablement, object/transform-array references, raw/empty values and instance-parameter set/replace/clear automatically invalidate both SceneRevision and InspectionRevision without a manual notification prerequisite.
- [x] Revision snapshots/comparisons are O(1), scene-local and backed by fixed, owned lifetime-qualified bookkeeping. Either getter order accounts for a change in both domains; repeated reads without edits remain stable; multiple edits and change-away/change-back cannot revive an old observation. Independent Scenes stay independently qualified. Normal explicit-signal invalidation remains effective. Do not use a global always-changing clock, fingerprints, walks, growing observation history or an unqualified raw epoch pointer.
- [x] Root-visible owner state is safe before root construction. Retained object-containing Layers remain safe to access, locally edit and destroy after their Scene dies. Detached object-containing payloads remain safe after their Layer dies while the Scene lives, and after the Scene dies. Object resolution and cleanup never dereference an expired Layer, Scene or object pool. Preserve exactly balanced object-use counts while the Scene remains live, including a detached payload destroyed after its former Layer. Allocation reuse cannot revive expired ownership.
- [x] Copy/assignment into an attached node preserves destination attachment and correct object resolution, including assignment from a detached value or another Layer in the same Scene followed by source destruction. Preserve existing self-assignment semantics. Genuine move-out invalidates the changed live source while keeping it safe for later edits; the moved-out value is detached. Reserve/append relocation preserves attachment, node identity and precise histories without pretending to be an editable move-out. Do not reinterpret object indices across Scenes or invent unsupported transfer behavior.
- [x] Detached construction/copying and insertion temporaries are not attached edits. Qualify root storage, ordinary and chosen-slot storage, failed insertion temporaries, gaps and reuse for ownership safety even though automatic membership validity is delivered in 02. Do not blindly notify from constructors/destructors. Any required generic Forest binding seam is minimal, optional/default-neutral and Scene-independent; existing Forest/Data Tree behavior remains unchanged.
- [x] Preserve existing precise editVersion/transformVersion, ordered ancestor histories, node lifetimes/topology identities, value/default/SRT semantics and object-use counts. Instance-parameter dependency invalidation must not silently advance unrelated existing precise edit/transform histories. Existing grouped edits and conditional restoration regressions remain unchanged.
- [x] Counting UpdateDelegates prove no extra render/UI callbacks from raw setters, assignment or direct value operations. Existing helpers and explicit signals keep their exact callback delivery. Structural Layer edit batching and update-batch work coalescing retain their distinct behavior. Do not migrate callers or overhaul the notification contract.
- [x] TDD through the existing public headless seam with real Scenes covers every payload operation above, both getter orders, stable reads, independent Scenes, explicit controls, change-back, actual owner destruction, source/destination copy/assignment, self-assignment, move-out versus relocation, object-count balance and expired-owner reuse. Tests include negative controls for detached construction, reserve and rejected lookup, not only successful explicit notifications or private epoch controls.
- [x] Reuse existing configured build trees with CUDA/UI/network/Lua/SDL3 enabled; build and freshly install changed libraries before runtime verification. Run positive new public cases, existing integration/broad-editing identity/edit/restore regressions and supporting Scene/Forest/Data Tree tests. Existing object/reference/array-unmap/active-Layer/filter/metadata invalidation remains green. Run available sanitizers or Valgrind on owner destruction, copy/move/assignment and relocation cases; record actual commands/counts/tool exits and honest coverage limits. Formatting passes and independent review covers ownership and revision coherence.
