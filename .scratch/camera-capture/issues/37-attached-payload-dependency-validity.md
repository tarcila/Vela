## Current behavior

Split from34 before source changes. Read34's complete criteria/Comments, resolved29 and implemented35/36. Payload `noteEdit()` advances precise local histories but not whole-scene validity; instance setters/clear do not call noteEdit. Both copy and move assignment currently transfer source m_layer to the destination. Move construction is also used during Forest storage relocation, while an actual move-out resets the attached source value and changes its history. Public Scene-owned shared Layers and detached copied temporaries can outlive their owners. Naive raw Scene epoch pointers or forwarding noteEdit through m_layer do not prove safe attachment or lifetime behavior.

## Desired behavior

- [ ] Attached public payload edits automatically invalidate both scene and inspection revisions: transform matrix/SRT/exact-state/default restoration, visibility, empty/raw value, object references/transform arrays, copy/move assignment and instance-parameter set/clear. Reproduce29 classes1–3 plus instance edits through actual public APIs without explicit signal controls. Change-away/change-back remains invalidated even with no intermediate reads. Repeated reads without writes remain stable; foreign Scenes retain qualified independent revisions.
- [ ] Destination attachment/ownership survives copy and assignment from another same-Scene Layer or a detached payload, including source Layer destruction. Public `layer()`, object resolution, use-count balance and subsequent invalidation belong to the destination. Detached construction/copies/temporaries are not attached edits. Move-out from a live node invalidates the changed source and leaves it safely attached for later edits; moved-out payload is detached. Forest reserve relocation preserves attachment and identities without becoming an editable move-out. Handle self-assignment consistently with existing precise history. No gratuitous API incompatibility or reinterpretation of cross-Scene object indices.
- [ ] Preserve precise editVersion/transformVersion, ancestry ordering/change-back, lifetime/topology identities, values/defaults/SRT and object-use counts. Instance-parameter dependency invalidation must not silently advance unrelated existing edit/transform histories. Copy/move/relocation semantics must be deliberately distinct; blindly emitting from constructors/destructors or transferring a source Layer pointer is not sufficient.
- [ ] Reuse/extend35/36's owned lifetime-qualified mechanism: O(1) revision reads, fixed bookkeeping, no query-time scene walk/fingerprint or growing observation history. Fold dependency changes consistently before all revision snapshots/comparisons; no getter acknowledges a change without invalidating both tokens. Keep signal-driven invalidation independent. Retained Layers and detached payloads never dereference newly dangling Scene/Layer/epoch/object-resolution pointers after either owner dies. Any generic Forest binding seam stays minimal, optional and Scene-independent, including root construction and reused slots; default Forest/DataTree behavior stays unchanged.
- [ ] Preserve exact render/UI UpdateDelegate delivery/counts and existing explicit notifications. No new coarse callbacks from raw setters/assignment. Preserve beginLayerEditBatch structural batching and beginUpdateBatch work coalescing. Automatic conservative validity is not a new notification contract; do not convert callers or modify unrelated modules.
- [ ] TDD real Scene mutations and lifetime cases: all payload entry points above; same-Scene cross-layer and detached copy/assignment followed by source destruction; destination invalidation; self-assignment; move-out versus reserve relocation; object-count balance; root payload; instance set/replace/clear with unchanged precise histories; retained Layer/temporary after Scene and Layer destruction; alternating getter order, stable reads, independent Scenes and explicit signals. Assert unchanged callbacks/batching/history. Use actual public APIs, not only epoch controls.
- [ ] Terminal qualification must rerun all six29 reproduction classes plus instance parameters and35/36's insertion/erase/clear/copy/reparent/removal/reuse/change-back cases together, including destination ownership, lifetime and generic Forest/DataTree regressions. Review34's original full checklist: every criterion must be satisfied across35–37, not deferred to28 or claimed from a partial repair. Preserve all existing broad-editing identity, node/ancestor histories, grouped local/world/mixed edits and restoration regressions.
- [ ] Reuse existing CUDA/UI/network/Lua/SDL3-enabled `_out/_cmake` and fresh `_out` install before positive new identity/Forest tests, existing integration/broad-editing regressions and full applicable CTest. Exercise memory-safety cases using available Valgrind/sanitizers where feasible. Record exact commands, actual positive case/assertion counts and explicit limitations, without cold configure/CUDA disable/absent matches/fake sanitizer claims. Bounded text logs only in `.scratch/camera-capture-logs/37-*`.
