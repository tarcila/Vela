## Acceptance criteria

- [ ] Add public headless bounds request construction and thin admitted MCP `vsr_bounds(request_id, scene_id, optional include_disabled)`. In this slice omission and explicit false mean active layers and effectively enabled contributors. Bind the original visibility choice and effective default to canonical identity using existing request rules; test omission/explicit-false retry behavior explicitly. Explicit true and any node_handle are rejected as unsupported before admission, never ignored or treated as the default scene query. Ticket 26 adds true; 22 adds node targets.
- [ ] Provide a host-owned complete scene value binding with exact scene identity, revisions actually covered, default-visible selection, source kind and world min/max. Refresh/replacement is bounded owning-thread safe-point work. Inspection never stamps an arbitrary supplied box current. Available observations return matched scene/target provenance and independently correct literal world min/max. Support available, empty, pending and unavailable; pending is only an explicit supplied host state. Missing binding, incomplete coverage and empty content never manufacture a zero box.
- [ ] Reject nonfinite/reversed boxes and foreign/stale identity or revisions before publication. Establish conservative whole-scene notification coverage with real Scene tests for geometry parameter/reference changes, array writes/unmap, node/local/ancestor transforms, visibility/filtering, active-layer changes, structure/membership, removal/reuse and change-back. An old successful-render revision remains stale after edits and failed synchronization; CPU observations do not require ready rendering. Host refresh at newly covered revisions restores availability without device work.
- [ ] Use fixed validated defaults: 256 node/geometry steps and 4096 vertex values per slice, 4096 nodes and 1,048,576 vertex values per operation, five seconds from admission, and at most 8MiB shared temporary bounds scratch. Validate the fixed policy before admission; do not invent scan counters for value-only observations. Ticket 26 adds configurable policy. Define an explicit finite binding/cache entry and byte budget with observable eviction; bound values/results, reserve/release through shared accounting, and do not retain growing identity history or unbounded diagnostic strings. Tests may exhaust finite capacity using supplied values/held existing inspection work rather than changing the bounds policy.
- [ ] Preserve current scene read authority at execution, publication and retrieval; owner minimal receipts after withdrawal contain no scene/box/provenance payload. Reuse request admission/replay/conflicts, operation status/cancel, bounded result retention and queue-inclusive deadlines. Retained results preserve historical revisions, not fresh observations. Eviction cannot revive old identities; cache misses/stale values have bounded machine-readable reasons. Cancellation, deadline, failure and rejected admission release temporary reservations.
- [ ] TDD one public behavior at a time with real Scenes and independently supplied literal world boxes. Prove all four states, missing/incomplete/invalid/stale values, default-visible provenance, complete notification coverage, old provider revision after failed sync, safe host refresh, shared scratch exhaustion/release, finite storage eviction, cancellation before execution, queue deadline and read withdrawal. Thin MCP proves tool exposure, admission/polling, defaults, unsupported true/node rejection, replay/conflicts and payload suppression. No scanner, callback, GPU/driver or capture qualification is inferred.
- [ ] Build/install changed libraries using existing `_out/_cmake` and installed `_out` before tests. Run positive new cases and existing integration/broad-editing regressions with CUDA/UI/network/Lua/SDL3 enabled. Record exact commands/case counts and limitations. No fresh configure, cold build, CUDA disable, absent test match or success-with-skip claim.
